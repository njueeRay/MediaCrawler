## 二、Bug 清单与根因

### Bug 1 — `FEISHU_BITABLE_APP_TOKEN` 变量名错误
**文件：** `api/services/feishu_service.py` line 38  
**表现：** WebUI 飞书连接检测始终返回失败  
**根因：** 变量名与 `.env` 不一致（`.env` 用的是 `FEISHU_APP_TOKEN`）  
**修复：** `FEISHU_BITABLE_APP_TOKEN` → `FEISHU_APP_TOKEN`  
**经验：** 环境变量名要有唯一来源（constants 或 `.env.template`），服务层不能硬编码字符串。

---

### Bug 2 — dotenv inline 注释污染 value
**文件：** `.env`  
**表现：** `SAVE_DATA_OPTION` 被解析为 `sqlite"  # WebUI需要SQLite ...`（含引号和注释），导致所有 DB 路由返回 400  
**根因：** Python `python-dotenv` 在 `KEY="value"  # comment` 格式下，将注释内容作为 value 一部分（带末尾引号）  
**修复：** 所有 `.env` 的 inline 注释移至独立行  
**经验：**
```ini
# 正确写法
# 数据存储方式：csv / sqlite / mysql
SAVE_DATA_OPTION="sqlite"

# 错误写法（dotenv 会截取注释进 value）
SAVE_DATA_OPTION="sqlite"  # WebUI需要SQLite
```

---

### Bug 3 & 4 — `FeishuReadConfig` 遗留 XHS 默认值
**文件：** `feishu_sync/config.py`  
**表现：** Step 3 (read_from_feishu) 返回 0 条；或抛 `FieldNameNotFound` 异常  
**根因：** `VIEW_ID = "vewT7xrAZ5"`（XHS 视图 ID）、`SELECT_FIELDS = "作品链接,..."` 均为小红书的硬编码值，微信表完全不适用  
**修复：** 两字段均清空为 `""`，表示"使用飞书默认"  
**经验：** 配置类的**默认值**是坑的高发区——尤其是从一个平台 copy 到另一个平台后。每次新业务上线前，要 grep 检查所有 `Config` 类是否有残留的平台特定字符串。

---

### Bug 5 — `success == 0` 误判为失败
**文件：** `sync_to_feishu.py`（3处）  
**表现：** Step 2 幂等去重后，exit code 为 1，WebUI 显示同步失败  
**根因：** 去重模式下新增 0 条是**完全正常**的行为，但代码用 `if success == 0: sys.exit(1)` 拦截了这种情况  
**修复：** 3处 `success == 0` → `failed > 0`  
**经验：**
- 幂等操作的成功判定应以"是否有失败"为准，而非"是否有新增"
- 区分三类结果：新增/跳过（去重）/失败，日志应分别打印

---

### Bug 6 — `sync_file()` 分支路由短路 JSON 展开路径
**文件：** `sync_to_feishu.py`  
**表现：** Step 4（`--file + --json-columns + --append-table-id`）进入了错误的 `_build_append_records` 分支，触发本地图片路径查找 → 崩溃  
**根因：** 函数内 `if append_table_id:` 分支早于 `if json_columns:` 分支，导致同时传两个参数时走了错误路径  
**修复：** JSON 列展开分支提前到 `append_table_id` 分支之前：
```python
# 正确顺序：先判断 json_columns（展开模式）
if json_columns:
    ...
# 再判断 append_table_id（append 模式）
elif append_table_id:
    ...
```
**经验：** 多条件路由函数，要用注释明确标注"互斥"与"优先级"，并补充边界用例的单元测试。

## 三、通用经验提炼

### 3.1 Windows 开发环境 UTF-8 陷阱
- Python subprocess 在 Windows GBK 下打印 emoji 会 `UnicodeEncodeError`
- **解法：** `set PYTHONUTF8=1` 或在 `.env` 添加 `PYTHONUTF8=1`
- subprocess 调用时同样需要 `env={...os.environ, "PYTHONUTF8": "1"}`

### 3.2 子进程日志逐行 parse 的健壮性
`feishu_service._run_sync_subprocess()` 用正则从子进程输出解析 success/failed 计数：
```python
m = re.search(r"成功.*?(\d+)", line)
```
这种方式脆弱——日志格式一变就失效。**推荐：** Step 2/4 结束时输出一行机器可读 JSON：
```
SYNC_RESULT: {"success": 67, "failed": 0, "skipped": 5}
```
父进程解析这一行即可，其余日志只做展示用。

### 3.3 `_build_sync_command` 目前不支持 Step 3/4 参数
`feishu_service._build_sync_command()` 仅构建 Step 2（`--db --db-type sqlite`）命令。
Step 3（read_from_feishu）和 Step 4（`--file --json-columns --append-table-id`）需在 `scheduler_service.subscription_combo` 流程中**独立实现**（不复用 `_build_sync_command`）。

### 3.4 workflow.env 是 Step 3/4 参数的唯一来源
`scripts/wechat_feishu_workflow.env` 中有完整的 Step 3/4 参数（TABLE1_ID、TABLE2_ID、JSON_COLUMNS、TABLE1_FILTER_*、VIEW_ID 等），WebUI 的 `task_config` 字段设计应以此文件为参考基线。

  --range-start 1 --range-end 1
