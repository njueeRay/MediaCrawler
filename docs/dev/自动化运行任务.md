
# 自动化运行任务（飞书读表去重 + 可配置全流程）

本文档用于规划并落地两项新增能力：

1. **上传前去重**：每次同步到飞书多维表格前，先从远程多维表格读取“已存在的笔记ID集合”，与本次待上传数据做去重后再上传。
2. **自动化触发同步任务**：支持定时/守护/按需触发爬虫 + 清洗 + 去重 + 飞书同步的全流程，且**任务全流程可配置**。

适用现状（基于仓库现有实现）：

- 已具备读表能力：`feishu_sync/read_from_feishu.py` + `FeishuSyncManager.search_records()`
- 已具备同步能力：`sync_to_feishu.py`（统一 CLI 入口）
- 已有自动化样例：`auto_scheduler.py`（schedule + watchdog），但当前以“文件监测/定时 + 直接同步”为主，配置粒度与流程编排能力不足。

---

## 一、需求理解与边界

### 1) 上传前去重（强约束）

目标：

- 任何一次“准备写入多维表格”的操作，都必须先读取表内已存在的 `笔记ID`，对即将写入的记录按 `笔记ID` 去重。

关键点：

- **去重源**：飞书多维表格远端数据（而不是本地文件、数据库）。
- **去重键**：默认 `笔记ID` 字段；后续要可配置（例如不同平台/表结构可能叫 `note_id`/`aweme_id`）。
- **幂等**：同一批文件/同一批记录重复执行，不应重复写入。

非目标（本次不强求，但建议预留）：

- 基于“记录内容 hash”或多字段组合去重。
- 飞书端“唯一约束”能力（多维表格本身不提供强唯一索引，需靠客户端控制）。

### 2) 自动化触发同步任务（全流程可配置）

目标：

- 设计一个配置驱动的任务：触发 → 运行爬虫 → 产出数据 →（可选）清洗/筛选 → 读表去重 → 同步飞书 → 记录结果/告警。

关键点：

- **触发方式**：
	- 手动单次执行（once）
	- 守护进程定时执行（daemon schedule）
	- 文件落地后触发（watch dir）
	- （可选）飞书事件触发：`feishu_ws_listener.py` 已存在，可作为未来扩展
- **全流程可配置**：至少要能配置“数据源（爬虫参数）/数据路径/去重规则/飞书目标表/同步批量大小/失败重试”。
- **并发与锁**：避免同一任务在上一次未完成时再次触发导致重复同步。

## 二、现有实现盘点（与新增功能的结合点）

### 读表

- `FeishuSyncManager.search_records(field_names, filter_info, page_size, view_id)`
	- 返回值为 `List[Dict]`（每条记录的 fields）
	- 支持分页
	- 支持按字段选择（field_names）和筛选（filter_info）
- `feishu_sync/read_from_feishu.py`
	- 已具备命令行读取、多条件过滤、导出 CSV

### 写表/同步

- `sync_to_feishu.py`
	- “统一 CLI”入口，支持单文件与目录
	- 走 `FeishuSyncManager` 的建表/建字段/批量写入
	- 目前缺少“上传前去重”步骤（新增点）

### 自动化调度

- `auto_scheduler.py`
	- 具备 schedule 定时 + watchdog 目录监控的雏形
	- 但配置多来自环境变量/代码常量，缺少“按任务定义流程”的编排层

## 三、新增功能 1：上传前读取飞书表进行去重

### 3.1 去重策略

核心：

1. 读取远端多维表格中已存在的 ID 集合 `existing_ids`
2. 从本次待写入记录中提取 `candidate_ids`
3. 实际写入集合 = `candidate_ids - existing_ids`

数学表达：设

- 远端已存在 ID 集合 $E$
- 本次待上传 ID 集合 $C$

则实际上传集合为：

$$U = C \setminus E$$

### 3.2 需要可配置的参数（建议）

建议在任务配置中提供：

- `feishu.app_token / table_id / view_id`：目标表定位
- `dedup.enabled`：是否启用（默认 true）
- `dedup.id_field`：去重字段名（默认 `笔记ID`）
- `dedup.remote_select_fields`：读取远端时只取该字段，减少带宽（默认 `["笔记ID"]`）
- `dedup.remote_filter`：可选过滤（例如只对某个 `type`、某个日期范围的记录做去重）
- `dedup.local_extract_paths`：从本地数据里提取 id 的路径（例如 JSON 里是 `note_id`，同步字段里叫 `笔记ID`）

说明：

- `FeishuSyncManager.search_records()` 已支持 `field_names`，因此最优做法是只拉取去重字段。
- 若远端数据量非常大（>10w），应增加 `view_id` 或过滤条件，或按时间窗口同步（推荐）。

### 3.3 接入点（建议改造位置）

建议把去重逻辑接入 `sync_to_feishu.py` 的“上传前”阶段，覆盖下列两种写入路径：

- 标准 JSON 同步：`result = manager.sync_data(raw_data)` 之前
- 追加写入路径（append模式）：`manager._batch_create_records_with_sdk(records)` 之前

### 3.4 伪代码（设计稿）

```python
def fetch_existing_ids(manager, id_field: str, view_id: str | None) -> set[str]:
		rows = manager.search_records(field_names=[id_field], view_id=view_id, page_size=100)
		ids = set()
		for row in rows:
				value = row.get(id_field)
				if value is None:
						continue
				ids.add(str(value).strip())
		return ids


def filter_records_by_remote_dedup(raw_data: list[dict], existing_ids: set[str], local_id_key: str) -> list[dict]:
		result = []
		for item in raw_data:
				cid = item.get(local_id_key)
				if not cid:
						continue
				if str(cid).strip() in existing_ids:
						continue
				result.append(item)
		return result
```

### 3.5 落地注意事项

- **字段名一致性**：远端字段是同步后的“表字段名”（如 `笔记ID`），本地 JSON 字段可能是 `note_id`。
	- 推荐：在同步前先做“本地字段标准化/映射”，确保能稳定提取到去重键。
- **性能**：首次全量读取可能慢。
	- 可接受起步方案：只读 `笔记ID` 一列（已支持）。
	- 增强方案：按时间窗口同步（例如只同步最近 N 天），并在远端按同一窗口去重。
- **缺失ID**：本地记录没有 ID 的，默认跳过上传或报错（建议可配置策略：skip / fail）。
- **一致性**：如果同步过程允许并行执行多个任务，需要“任务锁/表锁”避免竞态。

## 四、新增功能 2：自动化触发爬虫同步任务（全流程可配置）

### 4.1 统一概念：任务（Job）与步骤（Steps）

将一次运行抽象为一个 Job：

- 输入：任务配置（平台、关键词、模式、数据路径、飞书配置、去重规则、重试策略…）
- 过程：steps 串行执行
- 输出：运行日志 + 运行结果（成功/失败、写入条数、耗时、飞书表链接等）

建议的 steps：

1. `crawl`：运行 `main.py`（或 API 调用）产出数据到 `data/<platform>/...`
2. `select_input`：选取本次要同步的文件（按时间/模式/匹配 pattern）
3. `clean`（可选）：执行轻量清洗或自定义脚本
4. `dedup_remote`：读取飞书表已存在 id 做去重
5. `sync_feishu`：调用 `sync_to_feishu.py` 或其内部函数进行写入
6. `post`：运行后处理（写运行报告/发送告警/归档文件）

### 4.2 触发方式设计

建议支持三种触发，优先级从易到难：

1. **手动 once**（开发自测/运维常用）
2. **定时 daemon**（每天/每小时同步）
3. **目录监听 watch**（爬虫产出文件后自动触发）

仓库中 `auto_scheduler.py` 已有 schedule + watchdog 的基础，可作为现有入口的演进。

### 4.3 任务配置文件（建议结构）

建议新增一个“任务配置文件”，例如 `config/automation_tasks.yaml`（格式可选 YAML/JSON；YAML 更适合可读性）。

示例（设计稿）：

```yaml
version: 1

globals:
	python: "python"           # or "uv run"
	data_root: "data"
	logs_dir: "logs/automation"
	lock_dir: "cache/locks"

feishu:
	app_id_env: "FEISHU_APP_ID"
	app_secret_env: "FEISHU_APP_SECRET"
	app_token_env: "FEISHU_APP_TOKEN"
	table_id_env: "FEISHU_TABLE_ID"
	view_id_env: "FEISHU_VIEW_ID"

jobs:
	- name: "xhs_search_daily"
		enabled: true

		trigger:
			type: "schedule"        # schedule | watch | manual
			cron: "0 2 * * *"        # 若用 APScheduler/CronTrigger；如继续使用 schedule，则用 at: "02:00"
			at: "02:00"             # schedule 方案

		crawl:
			enabled: true
			command: ["uv", "run", "main.py"]
			args:
				- "--platform"; "xhs"
				- "--lt"; "qrcode"
				- "--type"; "search"
				- "--save_data_option"; "json"

		input:
			dir: "data/xhs/json"
			pattern: "*.json"
			pick:
				strategy: "mtime_last_minutes"
				minutes: 180

		dedup:
			enabled: true
			id_field_remote: "笔记ID"   # 飞书表字段
			id_field_local: "note_id"   # 本地JSON字段
			missing_id: "skip"          # skip | fail

		sync:
			enabled: true
			tool: "sync_to_feishu.py"
			batch_size: 50
			append_table_id: ""        # 可选：锁定目标表

		retry:
			times: 2
			backoff_seconds: 30
```

说明：

- `command` 用 list 表示，避免 shell 拼接注入问题。
- `pick.strategy` 用来决定“本次同步哪些输出文件”，否则目录可能越积越多。

### 4.4 幂等/锁/重试/观测性

- **任务锁**：每个 job 运行前尝试获取锁（例如 `cache/locks/<job>.lock`）。若锁存在且未过期，则跳过或等待。
- **写入幂等**：依赖“远端去重”保证重复执行不重复写入。
- **失败重试**：按 job 配置对“同步失败/网络失败”进行重试（注意不要对“参数错误”等永久失败盲目重试）。
- **运行记录**：输出 `logs/automation/<job>/<yyyy-mm-dd>.log`，并写一份结构化 `run_history.jsonl` 便于后续审计。

## 五、落地实施建议（任务规划）

> 这里给出从“可用”到“生产级”的迭代路径，优先保证正确性与可回滚。

### 阶段 A：在 `sync_to_feishu.py` 加入远端去重（必须）

1. 在同步前增加 `--dedup-remote` 开关（默认 true 或提供显式开关）
2. 增加参数：
	 - `--dedup-id-field`（默认 `笔记ID`）
	 - `--dedup-local-id-key`（默认 `note_id`，可按数据类型切换）
	 - `--dedup-view-id`（默认使用 `FEISHU_VIEW_ID` 或空）
3. 同步前执行：
	 - `existing_ids = fetch_existing_ids(...)`
	 - `raw_data = filter_records_by_remote_dedup(...)`
4. 输出统计日志：
	 - 远端已有数、输入数、去重后数、跳过缺失ID数

### 阶段 B：统一自动化入口配置（推荐）

1. 新增 `docs/dev/自动化运行任务.md`（即本文）定义配置规范
2. 以 `auto_scheduler.py` 为基础：
	 - 支持从任务配置文件加载 jobs
	 - 将 “daily/hourly/watch” 改为按 job 定义执行 steps
3. 保留“手动 once”能力：便于自测与回归

### 阶段 C：扩展触发与告警（可选）

- 接入 `feishu_ws_listener.py`：用飞书消息/多维表格某个字段变更触发 job
- 增加失败告警：飞书消息/邮件/webhook（按现有通知基础设施选型）

## 七、验收标准（建议）

### 去重

- 同一批数据重复执行 2 次：第二次实际写入条数应为 0（或极少数因缺失ID被跳过）。
- 去重统计日志清晰可追踪：输入/去重后/写入成功数一致。

### 自动化

- 可通过配置新增/禁用任务，而无需改代码。
- 任务支持 once 与 daemon 两种运行模式。
- 同任务重复触发不会并发重复写入（有锁或有串行保障）。
