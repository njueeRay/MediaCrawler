# MediaCrawler WebUI — 系统架构总览

> 版本: v0.1 Draft | 日期: 2026-02-11

---

## 1. 项目愿景

将 MediaCrawler 的爬虫采集、数据管理、字段映射、飞书同步、自动化调度等能力，统一到一个**可视化 Web 控制台**中，实现：

- **零命令行操作**：所有配置、运行、监控均通过网页完成
- **统一数据视图**：8 大平台的内容以统一表格呈现，支持自定义字段与过滤
- **订阅驱动采集**：以「订阅创作者」为核心，持续跟踪内容更新
- **灵活数据编排**：字段可重命名、选择、排序，按需格式化后同步到飞书
- **自动化运行**：定时任务编排，实现「配置一次、自动运行」的工作流

## 3. 核心数据流

### 3.1 订阅 → 采集 → 浏览 → 同步 主链路

```
 ① 订阅创作者           ② 定时/手动采集         ③ 数据入库
┌──────────┐         ┌──────────────┐        ┌──────────────┐
│ WebUI    │ ──API──▶│ CrawlerMgr   │──爬虫──▶│ DB / CSV     │
│ 搜索+订阅│         │ (subprocess) │        │ (统一存储)   │
└──────────┘         └──────────────┘        └──────┬───────┘
                                                     │
 ⑥ 同步到飞书          ⑤ 字段映射转换          ④ 数据浏览
┌──────────┐         ┌──────────────┐        ┌──────┴───────┐
│ 飞书多维  │◀──API──│ Formatter +  │◀──API──│ WebUI        │
│ 表格      │        │ FieldMapping │        │ DataExplorer │
└──────────┘         └──────────────┘        └──────────────┘
```


## 5. 与现有代码的集成策略

> **核心原则：二次开发，非另起炉灶。** 所有新增功能均在现有 `api/`、`database/` 目录内扩展，不创建平行结构。

### 5.1 现有代码清单与集成方式

| 现有文件 | 集成方式 | 具体变更 |
|----------|----------|----------|
| `api/main.py` | ✏️ **修改** | 新增 `include_router` 注册 5 个新路由；添加 startup 事件初始化 WebUI 表 |
| `api/routers/__init__.py` | ✏️ **修改** | 新增导出 `config_router`, `subscription_router` 等 5 个 router |
| `api/routers/crawler.py` | ✅ **原样复用** | 不做改动，WebUI 前端直接调用其已有接口 |
| `api/routers/data.py` | ✏️ **小幅扩展** | 新增 `?mapping_scheme_id=` 参数，查询时可选应用字段映射 |
| `api/routers/websocket.py` | ✏️ **小幅扩展** | 新增 `/ws/sync` 端点用于飞书同步进度推送 |
| `api/schemas/__init__.py` | ✏️ **修改** | 新增导出新 Schema 模块 |
| `api/schemas/crawler.py` | ✅ **原样复用** | 已有的 Enum/Request/Response 保持不变 |
| `api/services/__init__.py` | ✏️ **修改** | 新增导出新 Service 单例 |
| `api/services/crawler_manager.py` | ✅ **原样复用** | 新增的 SchedulerService 通过它启动爬虫子进程 |
| `database/models.py` | ✅ **不修改** | 现有 24 个模型保持不变 |
| `database/db_session.py` | ✅ **直接复用** | 新服务使用 `get_session()` 做数据库操作 |
| `database/db.py` | ✏️ **小幅修改** | `init_db()` 中引入 WebUI 模型以确保 `create_all` 包含新表 |
| `feishu_sync/` | ✅ **封装调用** | `FeishuService` 内部调用其 `sync_manager` / `data_formatter` |
| `auto_scheduler.py` | ✅ **参考逻辑** | `SchedulerService` 参考其任务定义，以 APScheduler 重新封装 |
| `config/*.py` | ✅ **读取** | `ConfigService` 读取其配置定义，向前端暴露分组信息 |

### 5.2 关键集成点详解

#### A. api/main.py 变更示意

```python
# === 现有代码 (保持) ===
from .routers import crawler_router, data_router, websocket_router
app.include_router(crawler_router, prefix="/api")
app.include_router(data_router, prefix="/api")
app.include_router(websocket_router, prefix="/api")

# === 新增代码 ===
from .routers import (config_router, subscription_router,
                       field_mapping_router, feishu_router, scheduler_router)
app.include_router(config_router, prefix="/api")
app.include_router(subscription_router, prefix="/api")
app.include_router(field_mapping_router, prefix="/api")
app.include_router(feishu_router, prefix="/api")
app.include_router(scheduler_router, prefix="/api")

@app.on_event("startup")
async def startup_init_webui():
    """确保 WebUI 新增数据库表已创建 & 种子数据已初始化"""
    from database.webui_models import init_webui_tables
    await init_webui_tables()
```

#### B. database/ 新模型文件策略

```python
# database/webui_models.py (新建)
# 导入 SAME Base，确保与现有模型共享元数据
from database.models import Base
from sqlalchemy import Column, Integer, String, Text, Boolean, DateTime, JSON, ...

class Subscription(Base):
    __tablename__ = "webui_subscription"
    ...

class FieldMappingScheme(Base):
    __tablename__ = "webui_field_mapping_scheme"
    ...
# ... 其余 WebUI 专用模型

async def init_webui_tables():
    """仅在首次运行时创建 webui_ 前缀的表"""
    from database.db_session import get_async_engine
    engine = get_async_engine()
    if engine:
        async with engine.begin() as conn:
            await conn.run_sync(Base.metadata.create_all)
        # 初始化种子数据 (默认字段映射方案)
        await _seed_default_mappings()
```

**为什么不修改 `database/models.py`：**
- 现有文件 494 行、24 个模型，是爬虫核心；修改有引入 bug 的风险
- WebUI 模型在逻辑上独立，使用 `webui_` 表前缀隔离
- 通过共享同一个 `Base`，`create_all()` 能同时覆盖所有表

#### C. 新服务使用现有 DB Session

```python
# api/services/subscription_service.py
from database.db_session import get_session
from database.webui_models import Subscription

class SubscriptionService:
    async def list_subscriptions(self, platform=None, page=1, size=20):
        async with get_session() as session:
            query = select(Subscription)
            if platform:
                query = query.where(Subscription.platform == platform)
            result = await session.execute(query.offset(...).limit(...))
            return result.scalars().all()
```

#### D. 新服务复用 CrawlerManager

```python
# api/services/scheduler_service.py
from api.services.crawler_manager import crawler_manager

class SchedulerService:
    async def execute_crawl_task(self, task_config):
        """将定时任务的配置转换为 CrawlerStartRequest，调用现有 manager"""
        request = CrawlerStartRequest(
            platform=task_config["platform"],
            crawler_type=task_config["crawler_type"],
            ...
        )
        return await crawler_manager.start(request)
```

### 5.3 与 wechat-article-exporter 的关系

```
                         不变
wechat-article-exporter ─────────▶ 独立运行的微信数据源服务
         │
         │  /api/public/v1/*
         ▼
MediaCrawler (WeChatClient) ────▶ 消费其 API 获取微信数据
         │
         │  统一存储到 DB
         ▼
WebUI ──────────────────────────▶ 展示微信数据 (与其他平台统一视图)
```

wechat-article-exporter 保持独立运行，WebUI 通过 MediaCrawler 的微信爬虫模块间接获取数据。WebUI 的配置管理模块可管理 `WECHAT_API_BASE_URL` 和 `WECHAT_AUTH_KEY` 连接参数。

## 6. 安全与部署

### 6.1 安全考虑

- **本地优先**：默认绑定 `127.0.0.1`，仅本机访问
- **可选认证**：通过 `.env` 配置是否启用登录（`WEBUI_AUTH_ENABLED=true`）
- **敏感配置脱敏**：API Key 等在前端显示时掩码处理（`FEISHU_APP_SECRET → ****secret`）
- **CORS**：仅允许同源请求

### 6.2 部署模式

```
开发模式:
  Terminal 1: uvicorn api.main:app --reload --port 8080
  Terminal 2: cd webui-src && npm run dev (Vite dev server, proxy to 8080)

生产模式:
  npm run build → 输出到 api/webui/
  uvicorn api.main:app --port 8080 (静态文件由 FastAPI 托管)
```
