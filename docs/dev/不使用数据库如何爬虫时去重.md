在MediaCrawler项目中，如果不使用数据库，可以通过以下几种方式保证同一关键词多次爬取时的数据去重：

## 主要去重策略

### 1. 分页控制避免重复爬取
通过配置`START_PAGE`参数控制爬取起始页码，避免重复爬取已处理的内容 [1](#0-0) ：

```python
START_PAGE = 1  # 爬取开始页数 默认从第一页开始
```

各平台爬虫都使用这个参数来跳过已爬取的页面，例如小红书爬虫 [2](#0-1) ：
```python
start_page = config.START_PAGE
while (page - start_page + 1) * xhs_limit_count <= config.CRAWLER_MAX_NOTES_COUNT:
    if page < start_page:
        utils.logger.info(f"[XiaoHongShuCrawler.search] Skip page {page}")
        page += 1
        continue
```

### 2. 文件存储模式的去重机制
项目支持CSV、JSON、Excel等文件存储方式 [3](#0-2) 。虽然文件存储本身没有数据库那样的唯一约束，但可以通过以下方式实现去重：

#### Excel存储（推荐）
Excel存储支持多工作表和专业格式化 [4](#0-3) ，便于后续手动去重和数据分析：
```bash
uv run main.py --platform xhs --lt qrcode --type search --save_data_option excel
```

#### CSV/JSON存储
使用CSV或JSON存储时，数据会保存在`data/{platform}/`目录下 [5](#0-4) ，可以通过脚本进行后处理去重。

### 3. 爬取数量控制
通过`CRAWLER_MAX_NOTES_COUNT`限制每次爬取的总数量 [6](#0-5) ，配合分页控制实现增量爬取：
```python
CRAWLER_MAX_NOTES_COUNT = 15  # 爬取视频/帖子的数量控制
```

## 实际使用建议

### 分批次爬取策略
1. **第一批次**：使用默认配置爬取
   ```bash
   uv run main.py --platform xhs --lt qrcode --type search --save_data_option excel
   ```

2. **后续批次**：调整`START_PAGE`继续爬取
   ```bash
   # 修改config/base_config.py中的START_PAGE为下一页
   START_PAGE = 3  # 从第3页开始
   uv run main.py --platform xhs --lt qrcode --type search --save_data_option excel
   ```

### 数据后处理
对于文件存储的数据，建议使用pandas进行去重处理：
```python
import pandas as pd

# 读取Excel文件
df = pd.read_excel('data/xhs/contents.xlsx')

# 基于唯一标识去重（如note_id）
df_dedup = df.drop_duplicates(subset=['note_id'], keep='first')

# 保存去重后的数据
df_dedup.to_excel('data/xhs/contents_dedup.xlsx', index=False)
```

## 注意事项

- 文件存储模式无法像数据库那样提供实时去重，主要依赖分页控制和后处理 [7](#0-6) 
- 如果需要更可靠的去重机制，建议使用SQLite数据库存储 [8](#0-7) 
- 各平台的搜索实现都遵循相同的分页控制模式，确保一致性 [9](#0-8) [10](#0-9) 

## Notes
- 项目主要通过配置参数控制爬取范围，而非内置的文件级去重机制
- Excel存储提供更好的数据管理能力，适合分批次爬取的场景
- 对于大规模数据去重需求，仍建议使用数据库存储方案
