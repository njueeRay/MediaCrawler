# 现阶段项目审阅建议（2026-02-12）

> 目标：提升“可用性 + 可观测性 + 可持续迭代”。

---

## 1. 结论摘要（先做什么）

### P0（影响可用/排障效率）
- **日志可观测性补齐**：必须能看到“历史运行日志 + 调度任务每次执行的日志/错误/耗时”。
- **调度可解释性补齐**：任务列表必须直观看到“触发周期/下次运行时间/最近一次运行结果/失败原因”。
- **关键链路失败要可自诊断**：例如微信搜索/采集依赖 auth-key 失效时，前端要提示“怎么修”。

### P1（体验与效率）
- 订阅管理支持“批量启停/批量删除/批量打标签/批量采集”闭环。
- 订阅采集状态持久化（落库），重启后仍可追溯。

---

## 2. 订阅管理模块完善建议

### 2.1 功能建议（按价值排序）
- **订阅状态持久化（P0）**：将 queued/running/success/failed + 最近一次采集时间 + 失败原因落库；重启不丢。
- **订阅维度采集记录（P0）**：每次采集生成一条“采集执行记录”（类似 scheduler executions），能查看日志/耗时/错误。
- **批量操作增强（P1）**：
  - 批量启用/禁用订阅
  - 批量删除（带二次确认 + 显示将删除数量）
  - 批量打标签（用于后续按标签调度/筛选）
- **筛选与检索（P1）**：按平台/状态/标签/最近更新时间筛选；支持关键词搜索订阅列表。
- **数据可追溯（P1）**：订阅行展示“最近一次内容时间/内容数增量（最近 24h/7d）”。

### 2.2 UI/交互建议
- **搜索结果卡片信息层级**：
  - 第一行：名称 + 平台 tag
  - 第二行：ID（弱化）
  - 第三行：简介/签名（如微信 signature）
- **订阅列表可读性**：
  - “采集状态”展示为 tag + tooltip（tooltip 显示失败原因/更新时间）
  - “最后采集/最后内容时间”为空时展示 `—`
- **错误提示可操作**：
  - 例如微信搜索失败提示中，直接告诉用户需要配置 `WECHAT_API_BASE_URL/WECHAT_AUTH_KEY` 并给出配置页入口。

### 2.3 数据质量与一致性
- **平台统一字段**：creator_avatar 统一 https；creator_url 尽量可点击；meta 字段保持平台差异但结构稳定。
- **幂等性**：前端快速多次点击“订阅/采集”要做到后端幂等或友好提示（避免重复创建 409 让用户困惑）。

---

## 3. 日志与排障能力（重点）

### 3.1 爬虫日志（Logs 页）
- **历史日志必须可加载**：至少支持最近 200/500 条。
- **日志内容建议**：增加 source（crawler/scheduler/feishu/ws）或上下文（task_id/execution_id）。

### 3.2 调度执行日志（TaskScheduler 页）
- **每次执行必须可看日志**：
  - 执行列表点“查看日志”弹窗展示 log_output
  - 失败时必须能看到 error_message + 最后 N 行日志
- **运行中可跟踪（可选增强）**：running 状态下可提供“刷新/流式”日志（SSE `/logs/stream`）。

---

## 4. 调度模块信息完善建议

### 4.1 任务列表最少需要的信息（P0）
- 调度类型与摘要（interval: 每 N 小时 / cron: 表达式）
- next_run_at（下次执行时间）
- last_run_at（上次执行时间）
- run_count / fail_count
- 最近一次失败原因（可用 last_error 或通过 executions 最新 failed 反查）

### 4.2 触发次数与频率
- 建议增加一个“近 24h 执行次数/失败次数”的聚合字段（避免只看累计 run_count 不知道近期是否在跑）。

---

## 5. 回归与质量门禁建议

- smoke suite 作为每次修改后的固定入口（已具备），建议后续：
  - 新增“调度执行日志读取”断言（`GET /scheduler/executions/{id}/logs`）
  - 新增“crawler 历史日志”断言（`GET /crawler/logs`）
- 对外部依赖（微信源/飞书）统一提供 `POST /config/test` 检测，并把检测信息联动到页面提示。

### 5.1 接口响应契约治理（新增，建议 P0）

- **后端统一响应契约**：
  - HTTP JSON 接口统一为 `{ code, message, data }`
  - 分页接口统一为 `{ code, message, data: { items, total, page, size, pages } }`
- **禁止裸结构返回**：新增/改造接口时不再返回 `{ files: [] }`、`{ status: 'ok' }` 这类裸对象。
- **前端统一解包**：在 API 层提供 `unwrapApiData()`，页面侧只读解包后的对象，避免散落 `data.data || data`。
- **自动化门禁**：smoke 增加关键接口“响应形状”断言（例如 `/crawler/logs`、`/data/files`、`/data/stats`）。

- **重要**: 做一次“接口返回结构 vs 前端取值方式”的全量对照审计：先抓出所有 webui-src 的 API 调用与解析模式，再对照 routers 返回是否统一。以及继续做“全接口契约扫描脚本”（自动找出 routers 中裸返回），并把它接到 CI

## 6. 建议的下一步落地顺序

1. 订阅采集状态持久化（落库/重启恢复）
2. 订阅采集执行记录（可查看日志/耗时/错误）
3. 接口响应契约 CI 校验（禁止裸响应回归）
4. 调度任务“近 24h 聚合指标 + 最近失败原因”
5. 订阅页批量启停/批量打标签
