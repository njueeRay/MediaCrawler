图片分享（item_show_type=8）的图片无法爬取，通常是因为其图片不存储在常规 `<img>` 标签中，而是通过 JavaScript 变量 `window.picture_page_info_list` 动态渲染，若该变量提取失败或 CDN 链接不可访问，就会导致图片丢失 [1](#1-0) 。

### 原因与定位

1. **图片分享的渲染逻辑**
   - 系统通过正则从 HTML 中匹配并执行 `window.picture_page_info_list` 的赋值语句，然后遍历数组生成 `<img src="${picture.cdn_url}">` [2](#1-1) 。
   - 同样的逻辑也用于预览组件和导出器 [3](#1-2) 。

2. **常见失败点**
   - **正则匹配不到**：HTML 结构变化或代码被压缩，导致 `window.picture_page_info_list` 无法被正则 `/(?<code>window\.picture_page_info_list\s*=.+\.slice\(0,\s*20\);)/s` 捕获 [4](#1-3) 。
   - **eval 执行失败**：在严格环境或 CSP 策略下，`eval(code)` 可能抛出异常，导致 `picture_page_info_list` 未定义 [5](#1-4) 。
   - **cdn_url 无效**：数组中的 `picture.cdn_url` 可能已失效、被防盗链或需要特定 Referer，下载时返回 403/404 [6](#1-5) 。
   - **代理/网络问题**：资源下载走代理池，若代理不可用或触发冷却，会导致图片下载失败 [7](#1-6) 。

3. **与普通图文的差异**
   - 普通图文通过 `querySelectorAll('img')` 提取 `src/data-src`，而图片分享依赖 JS 变量，若变量缺失则无图 [8](#1-7) 。

### 排查步骤

1. **检查 HTML 中是否存在 `window.picture_page_info_list`**
   - 在浏览器打开文章，查看源码或控制台搜索 `picture_page_info_list`。
2. **查看控制台错误**
   - 若有 “Failed to download … after 10 attempts” 或 “无可用代理”，按 Troubleshooting 检查代理与重试 [9](#1-8) 。
3. **手动验证 cdn_url**
   - 从 `picture_page_info_list` 复制 `cdn_url`，用 `curl -I` 测试是否可访问。
4. **导出时检查资源映射**
   - 在导出器 `normalizeHtml` 中，`urlmap` 应包含图片 URL 到本地路径的映射，若缺失则说明未下载成功 [10](#1-9) 。

### 临时方案

- 若正则失效，可放宽匹配模式或增加备用正则。
- 若 eval 被禁，可改用 `new Function` 或静态解析 JSON。
- 对防盗链 CDN，可在下载请求中添加 Referer 代理或使用图片代理（`IMAGE_PROXY` 配置） [11](#1-10) 。

## Notes
- 图片分享的图片数量上限为 20 张（`.slice(0, 20)`），超出部分不会被处理 [4](#1-3) 。
- 导出 HTML 时，图片会写入 `./assets/uuid.ext`，若下载失败则保留原始远程链接，导致图片无法显示 [12](#1-11) 。

要解决图片分享（item_show_type=8）无法获取正文和图片的问题，需从“提取变量→渲染图片→下载资源”三个环节增强容错与可用性。核心思路是：确保 `window.picture_page_info_list` 能被可靠提取、安全执行、并成功下载其 `cdn_url`。

### 一、增强变量提取与执行（解决正文无图）

1. **放宽正则匹配**：当前正则 `/(?<code>window\.picture_page_info_list\s*=.+\.slice\(0,\s*20\);)/s` 要求语句以 `.slice(0, 20);` 结尾，若微信改写或压缩则匹配失败 [1](#2-0) 。建议增加备用正则，例如：
   ```js
   const patterns = [
     /window\.picture_page_info_list\s*=.+?\.slice\(0,\s*20\);/s,
     /window\.picture_page_info_list\s*=\s*\[.+?\];/s,
     /window\.picture_page_info_list\s*=\s*(\[[\s\S]*?\]);/
   ];
   for (const p of patterns) {
     const m = html.match(p);
     if (m) { /* 使用 m[1] 或 m[0] */ break; }
   }
   ```

2. **避免 eval**：在 CSP 环境下 `eval(code)` 可能抛异常 [2](#2-1) 。可改用 `new Function` 或静态解析 JSON：
   ```js
   const jsonStr = code.replace(/^window\.picture_page_info_list\s*=\s*/, '').replace(/;$/, '');
   const picture_page_info_list = JSON.parse(jsonStr);
   ```

3. **容错处理**：若提取或解析失败，至少保留描述文本（`#js_image_desc`）并给出提示，避免页面空白 [3](#2-2) 。

### 二、确保图片成功下载（解决图片丢失）

1. **校验 cdn_url**：遍历 `picture_page_info_list` 时，先校验 `picture.cdn_url` 是否为有效 URL，并记录无效项用于日志 [4](#2-3) 。

2. **代理与重试**：图片下载走 `ProxyPool`，若代理不可用或触发冷却会导致失败 [5](#2-4) 。确保：
   - 代理池有可用实例（检查控制台“无可用代理”）。
   - 重试次数足够（默认 10 次） [6](#2-5) 。

3. **图片代理（防盗链）**：若 CDN 返回 403，可启用图片代理转发 Referer。在 `config/index.ts` 中配置 `IMAGE_PROXY`（默认空） [7](#2-6) ，例如：
   ```ts
   export const IMAGE_PROXY = 'https://image.baidu.com/search/down?thumburl=';
   ```
   然后在渲染时对 `cdn_url` 套一层代理。

4. **导出时检查资源映射**：HTML 导出通过 `normalizeHtml` 将远程 URL 替换为本地路径 [8](#2-7) 。若 `urlmap` 未包含图片 URL，说明下载未成功，需检查 `extractResources` 与 `processExportQueue` 是否正确收集了图片 URL（图片分享的图片由动态渲染生成，确保在 DOM 中存在后再提取） [9](#2-8) 。

### 三、统一修改点

- **渲染逻辑**：`utils/index.ts` 与 `components/preview/Article.vue` 的图片分享处理逻辑几乎一致，建议抽取公共函数 `renderImageShare(html, containerEl)`，避免重复维护 [10](#2-9) [11](#2-10) 。
- **导出集成**：在 `Exporter.normalizeHtml` 中，若检测到 `item_show_type===8`，可先执行图片分享渲染逻辑再提取资源，确保动态图片被加入下载队列 [12](#2-11) 。

### 四、临时调试方案

1. 在浏览器打开目标图片分享文章，控制台执行：
   ```js
   console.log(window.picture_page_info_list);
   ```
   若为 undefined，说明正则未匹配到，需调整正则。
2. 手动复制数组中的 `cdn_url`，用 `curl -I` 测试是否可访问；若 403，考虑启用 `IMAGE_PROXY`。
3. 导出后检查 `assets/` 目录，确认图片文件是否生成；若缺失，查看控制台下载错误日志。
