# 微信爬虫集成方案工作量评估

## 一、工作量拆解

| 模块 | 估算工作量 | 复杂度 | 说明 |
|------|-----------|--------|------|
| ① 项目脚手架 | 小 | ⭐ | 创建目录结构、配置文件、注册入口，纯模板代码 |
| ② WeChatMpClient 核心请求层 | 中 | ⭐⭐⭐ | 将 proxyMpRequest + CookieStore 从 TS 重写为 Python httpx |

| ⑥ 文章内容下载 + HTML 解析 | 中 | ⭐⭐⭐ | HTML 归一化、图片提取、格式转换 |

## 二、主要复杂度分析

### 🔴 复杂度最高：公众平台登录流程（④）

这是整个方案的**最大风险点**，原因：

1. **wechat_crawler 的登录本质上依赖浏览器环境**：用户在浏览器中扫码登录微信公众平台后台（`mp.weixin.qq.com`），Nitro 服务端只是作为 Cookie 代理中转。它**不是**在服务端模拟登录，而是前端登录后把 Cookie 转存到 `CookieStore`。

2. **MediaCrawler 其他平台用 Playwright 驱动浏览器**，但微信公众平台后台的登录有**多重验证**（扫码 + 管理员确认 + 可能的风控拦截），Playwright 自动化的稳定性未知。

3. **两套认证体系完全不同**：
   - 公众平台登录 → 拿到 `slave_sid` / `slave_user` 等 Cookie → 可调用 `searchbiz`、`appmsgpublish` 等后台接口
   - mitmproxy 凭证 → 拿到 `__biz`、`pass_ticket`、`wap_sid2` → 只能调用文章详情页面和评论接口

**实际可行的策略**：放弃 Playwright 自动化登录，改为：
- **方案 A**（推荐）：启动一个本地 Web 页面显示微信登录二维码，用户手动扫码，服务端接收 Cookie — 类似 wechat_crawler 的原始方式
- **方案 B**：直接让用户从浏览器 DevTools 手动复制 Cookie 粘贴到配置文件

### 🟡 复杂度次高：HTML 解析与归一化（⑥）

wechat_crawler 的 `shared/utils/html.ts` 使用 cheerio 做了大量 HTML 处理：
- 提取 `js_content` 主体
- 处理懒加载图片（`data-src` → `src`）
- 移除脚本/样式/广告元素
- 处理微信特有的 `mpvoice`、`mpprofile` 等自定义标签
- `parseCgiDataNew()` 解析页面内嵌的 CGI 数据（含 JS eval fallback）

用 BeautifulSoup 重写时，大部分是机械性翻译，但**边界情况多**（文章被删除、违规、图片分享、文本分享等不同类型，参考 `samples/` 目录下的各种 fixture）。

### 🟡 复杂度中等：反爬对抗（⑨）

- 微信对请求频率极其敏感，25 分钟凭证过期
- 需要在真实环境中反复调试请求头、Cookie 组合、间隔时间
- 这部分工作量**不可预测**，取决于微信当前的风控策略

## 三、AI Coding 预估完成时间

以 AI 辅助编码能力，按**交互式迭代**（提需求 → 写代码 → 测试反馈）来算：

| 阶段 | 内容 | 预估轮次 | 预估时间 |
|------|------|---------|---------|
| **Phase 1：骨架搭建** | 目录结构、配置、数据模型、存储层、main.py 注册 | 2-3 轮 | **1-2 小时** |
| **Phase 2：核心客户端** | `WeChatMpClient`、`proxyMpRequest` Python 重写、Cookie 管理 | 3-5 轮 | **2-3 小时** |
| **Phase 3：凭证管理** | mitmproxy 插件适配、`CredentialManager` | 1-2 轮 | **0.5-1 小时** |
| **Phase 4：文章获取** | 列表分页、详情下载、HTML 解析 | 3-5 轮 | **2-4 小时** |
| **Phase 5：登录流程** | 二维码展示、Cookie 持久化（取决于选择的方案） | 3-5 轮 | **2-4 小时** |
| **Phase 6：评论 + 补充** | 评论获取、公众号信息、格式导出 | 2-3 轮 | **1-2 小时** |
| **Phase 7：调试联调** | 真实环境测试、反爬调优、边界处理 | 5-10 轮 | **3-6 小时** ⚠️ |

### 总计：约 **12-22 小时** 的交互式开发

其中：
- **纯代码生成**（Phase 1-6）：AI 可快速产出，约 **8-15 小时**
- **调试联调**（Phase 7）：瓶颈在于需要真实微信环境测试，需要实际运行并反馈结果，**这是最不确定的部分**

## 四、建议的迭代策略

```
Phase 1 (MVP)
├── 凭证模式（credential）优先 → 绕过登录复杂度
├── 硬编码 fakeid → 获取文章列表
├── 下载文章 HTML → 存 JSON
└── 验证基本链路跑通

Phase 2 (核心功能)
├── HTML 归一化 + Markdown 转换
├── 评论获取
├── CSV/DB 存储适配
└── 代理池接入

Phase 3 (完善)
├── 公众平台登录支持
├── 搜索公众号
├── 增量爬取
└── 错误重试 + 高级反爬
```

**建议从 Phase 1 开始**，因为凭证模式不需要处理复杂的登录流程，能最快验证核心链路。手机上用微信打开一篇公众号文章，mitmproxy 抓到凭证后就能开始爬取。
