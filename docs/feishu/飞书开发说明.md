# 飞书多维表格数据同步方案

## 📋 项目概述

本方案旨在将 MediaCrawler 爬取的小红书数据自动同步到飞书多维表格，实现数据的可视化管理和分析。通过 Python 脚本调用飞书 API，支持批量同步、增量更新和实时监控。

## 🏗️ 系统架构

```
MediaCrawler (数据采集)
    ↓
数据格式化 (CSV/JSON → 飞书格式)
    ↓
飞书 API 客户端 (批量上传)
    ↓
飞书多维表格 (数据展示与分析)
```

### 核心组件

- **XHSDataFormatter**: 小红书数据格式化器
- **FeishuImageUploader**: 附件/图片上传器（素材上传）
- **FeishuSyncManager**: 同步流程管理器（建表/建字段/批量写入）
- **sync_to_feishu.py**: 统一 CLI（JSON/CSV、目录/通配符）

## 📊 数据表结构设计

### 主表：小红书笔记数据

| 字段名称 | 类型 | 说明 | 数据源 |
|---------|------|------|--------|
| 笔记ID | 单行文本 | 唯一标识 | note_id |
| 标题 | 单行文本 | 笔记标题 | title |
| 内容摘要 | 多行文本 | 描述内容(限500字) | desc |
| 类型 | 单选 | 图文/视频 | type |
| 发布时间 | 日期时间 | 原发布时间 | time |
| 用户昵称 | 单行文本 | 发布者昵称 | nickname |
| 点赞数 | 数字 | 互动数据 | liked_count |
| 收藏数 | 数字 | 互动数据 | collected_count |
| 评论数 | 数字 | 互动数据 | comment_count |
| 分享数 | 数字 | 互动数据 | share_count |
| 地理位置 | 单行文本 | IP定位 | ip_location |
| 标签 | 多选 | 内容标签 | tag_list |
| 搜索关键词 | 单行文本 | 爬取关键词 | source_keyword |
| 笔记链接 | 超链接 | 原文链接 | note_url |
| 热度评分 | 数字 | 综合热度计算 | 公式计算 |
| 爬取时间 | 日期时间 | 数据采集时间 | last_modify_ts |

### 热度评分算法
```
热度评分 = (点赞数×1.0 + 收藏数×2.0 + 评论数×3.0 + 分享数×4.0) / 10
```

## 🚀 实施步骤

### 第一步：飞书应用准备

1. **创建飞书应用**
   - 访问 [飞书开放平台](https://open.feishu.cn/app)
   - 创建企业自建应用：`小红书数据同步器`
   - 获取 App ID 和 App Secret

2. **配置权限**
   ```
   bitable:app - 多维表格应用权限
   bitable:app:readonly - 读取权限  
   bitable:app:readwrite - 写入权限
   ```

3. **创建多维表格**
   - 新建多维表格：`小红书数据分析`
   - 获取 App Token

### 第二步：项目结构

```
MediaCrawler/
├── feishu_sync/
│   ├── __init__.py
│   ├── config.py            # 配置管理
│   ├── data_formatter.py     # 数据格式化与字段定义
│   ├── image_uploader.py     # 素材上传（bitable_image/bitable_file）
│   └── sync_manager.py       # 建表/建字段/批量写入/图片绑定
├── sync_to_feishu.py         # 统一 CLI
└── .env                      # 环境配置
```

### 第三步：环境配置

1. **安装依赖**
   ```bash
   uv add lark-oapi python-dotenv pandas
   ```

2. **配置 .env 文件**
   ```bash
   # 飞书配置
   FEISHU_APP_ID=your_app_id_here
   FEISHU_APP_SECRET=your_app_secret_here  
   FEISHU_APP_TOKEN=your_app_token_here
   FEISHU_TABLE_ID=
   
   # 可选配置

   FEISHU_AUTO_SYNC=true

   ```

### 第四步：核心功能

#### 数据格式化特性
- **智能类型转换**: 自动处理时间戳、数字类型
- **文本清理**: 移除特殊字符，限制长度
- **标签解析**: 支持多种分隔符的标签字符串
- **链接脱敏**: 自动移除 `xsec_token`、`xsec_source` 等笔记链接私参，仅保留公开访问所需信息
- **去重处理**: 基于笔记ID自动去重
- **热度计算**: 加权算法评估内容热度

#### API限制处理
- **批量上传**: 每批最多500条记录
- **速率限制**: 请求间隔100ms防止限流
- **错误重试**: 自动重试机制
- **令牌管理**: 自动刷新访问令牌

## 📖 使用指南

### 基础使用

```bash
# 1. 同步单个 JSON/CSV 文件
uv run sync_to_feishu.py --file data/xhs/json/search_contents_2026-01-22.json

# 2. 同步目录
uv run sync_to_feishu.py --dir data/xhs/json/

# 3. 通配符批量同步
uv run sync_to_feishu.py --dir data/xhs/json/ --pattern "*_search_contents.json"
```

### 指定上传范围

可通过 `--range-start`/`--range-end` 限定上传范围（从1开始，包含结束条目）：

```bash
# 仅上传第 51-100 条
uv run sync_to_feishu.py --file data/xhs/csv/test-sample.csv \
   --range-start 51 \
   --range-end 100
```

### CSV JSON 列同步

当 CSV 某一列保存了 JSON（单对象或数组）时，可自动解析 JSON 字段并建表写入：

```bash
# 多个 JSON 列名为 activity_json、speaker_json，同时保留 city/type 两个普通列
uv run sync_to_feishu.py --file data/xhs/json/activity_export.csv \
   --json-columns activity_json,speaker_json \
   --json-keep-columns city,type \
   --json-table-name "活动JSON同步"
```

说明：
- JSON 会被自动扁平化（默认使用 "." 分隔）并映射为多维表字段。
- 可使用 `--json-flatten-sep "_"` 修改扁平化分隔符。
- 默认以 JSON 首字段作为飞书主字段，确保表格展示关键信息（可用 `--json-primary` 覆写）。

参数说明：
- `--json-column/--json-columns`：需解析为 JSON 的列名，支持多个，逗号分隔；旧参数 `--json-column` 依旧可用。
- `--json-table-name`：目标表名，未指定则使用默认名称。
- `--json-primary`：可选主字段名称，默认自动使用 JSON 首字段；仅在需要覆写时指定，若字段缺失仍会回退到 `row-N`。
- `--json-flatten-sep`：JSON 扁平化分隔符，默认 `.`。
- `--json-keep-columns`：与 JSON 记录同行写入的普通列；为空时会自动使用所有非 JSON 列。
- 多个 JSON 可以写在同一个单元格（以逗号/换行分隔），会按行展开并与 `--json-keep-columns` 指定的字段一一对应。
- JSON 同步使用批量新增接口（BatchCreate），仅追加记录，不会覆盖表中已有内容。

### 追加写入（CSV/JSON，忽略缺失字段）

当飞书表中存在源文件没有的字段时，默认会自动忽略并继续上传（仅新增，不覆盖）。
如需指定目标表，可使用 `--append-table-id`：

```bash
uv run sync_to_feishu.py --file data/xhs/your_file.csv \
   --append-table-id "tblxxxxxx" \
   --batch-size 50
```

也支持 JSON 文件：

```bash
uv run sync_to_feishu.py --file data/xhs/your_file.json \
   --append-table-id "tblxxxxxx"
```

### 追加时设置额外字段

如果需要在追加时额外写入一个固定字段（例如新增 `type=黑客松`）：

```bash
uv run sync_to_feishu.py --file data/xhs/your_file.csv \
   --append-table-id "tblxxxxxx" \
   --append-extra-field "type" \
   --append-extra-type 3 \
   --append-extra-value "黑客松" \
   --append-extra-options "黑客松,峰会,比赛"
```

说明：
- 若字段不存在会自动创建；字段存在则直接写入值。
- `--append-extra-options` 仅在单选/多选时生效，格式为逗号分隔。

#### 追加参数说明

| 参数 | 说明 | 示例 |
|---|---|---|
| `--append-table-id` | 指定目标表ID（覆盖环境变量 `FEISHU_TABLE_ID`） | `tblxxxxxx` |
| `--append-extra-field` | 额外字段名 | `type` |
| `--append-extra-type` | 字段类型编号 | `3` |
| `--append-extra-value` | 写入的固定值 | `黑客松` |
| `--append-extra-options` | 单选/多选选项（逗号分隔） | `黑客松,峰会,比赛` |

#### 字段类型编号对照

| 类型编号 | 含义 |
|---|---|
| `1` | 单行文本 |
| `2` | 数字 |
| `3` | 单选 |
| `4` | 多选 |
| `5` | 日期时间 |
| `15` | 超链接 |
| `17` | 附件 |

### 读取多维表格（筛选/选列/导出）

支持按字段过滤、只读取指定列，并导出为 CSV：

```bash
# 过滤“信息质量评估”包含“优质”或“缺失但值得溯源”，仅导出AI文本分析字段
uv run feishu_sync/read_from_feishu.py \
   --table-id "tblxxxxxx" \
   --filter-field "信息质量评估" \
   --filter-operator contains \
   --filter-values "优质,缺失但值得溯源" \
   --filter-conjunction or \
   --select-fields "AI文本分析" \
   --output-csv data/xhs/csv/feishu_export.csv
```

说明：
- `--filter-operator` 支持：`contains`、`doesNotContain`、`isEmpty`、`isNotEmpty`、`is`、`isNot`。
- `--select-fields` 仅返回指定字段，逗号分隔。
- 不指定 `--output-csv` 时默认输出 JSON 到终端。

### 集成到爬虫流程

在 `config/base_config.py` 中添加：
```python
# 飞书自动同步
ENABLE_FEISHU_AUTO_SYNC = True
```

在数据保存后自动触发：
```python
if config.ENABLE_FEISHU_AUTO_SYNC:
    os.system("uv run sync_to_feishu.py --dir data/xhs/ &")
```

## 🚨 注意事项

### API限制
- 飞书API有调用频率限制，建议批量操作
- 单次最多上传500条记录
- 访问令牌有效期2小时，需自动刷新

### 数据质量
- 确保CSV文件编码为UTF-8
- 时间戳格式需统一（毫秒或秒级）
- 大文本字段会被自动截断

### 多出来的首列“多行文本”说明
- 多维表格创建时会自动生成**主字段**（默认名称常为“多行文本”）。
- 主字段不可删除，但可以在表格中**手动重命名**。
- 若希望自动化命名，可在建表后通过字段更新接口重命名主字段（当前脚本未内置）。

### 安全建议
- 敏感配置使用环境变量
- 定期轮换应用密钥
- 监控API调用日志

## 🔍 故障排查

### 常见问题

1. **认证失败**
   - 检查App ID和Secret是否正确
   - 确认应用权限已正确配置

2. **上传失败**
   - 检查数据格式是否符合要求
   - 确认网络连接正常

3. **数据丢失**
   - 查看同步日志确认错误原因
   - 检查去重逻辑是否正确

```bash
# 查看成功率统计

```
