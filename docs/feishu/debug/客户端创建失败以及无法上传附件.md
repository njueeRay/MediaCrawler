
# 客户端创建失败以及无法上传附件（Debug 成功经验）

## 背景与现象
- 使用官方 Python SDK（lark-oapi）初始化客户端时失败，或上传附件时报错。
- 典型报错：
	- 表格创建或字段创建失败（SDK 类名/用法不匹配）。
	- 上传素材接口返回 `1061002 params error`。
	- 上传卡住或长时间无响应。

## 关键结论（可直接复用）
1. **SDK 创建表与字段要分开**：创建表用 `app_table.create`，字段用 `app_table_field.create`，不要在建表时传完整字段列表。
2. **附件上传必须填完整参数**：
	 - `parent_type`：多维表格图片用 `bitable_image`，非图片附件用 `bitable_file`。
	 - `parent_node`：多维表格 `app_token`。
	 - `extra`：`{"drive_route_token": "<app_token>"}`。
	 - `file_name`、`size`、`file` 必填。
3. **附件写入记录**：上传成功后把 `file_token` 写入附件字段（如 `图片`）。
4. **防止卡住**：SDK 客户端设置 `timeout`，避免上传无限等待。

## 实施要点（精炼版）
### 1) SDK 客户端创建
- 确保 `APP_ID/APP_SECRET/APP_TOKEN` 正确加载（.env）。
- 使用 SDK builder 创建客户端，并设置超时：
	- `Client.builder().app_id(...).app_secret(...).timeout(REQUEST_TIMEOUT).build()`

### 2) 表格与字段创建
- 先建表：`CreateAppTableRequestBody.table(AppTable.builder().name(...))`
- 再逐个建字段：`CreateAppTableFieldRequest` + `AppTableField`
- 表格重名（1254013）时自动追加时间戳重试。

### 3) 上传附件（素材上传）
- 按多维表格常见问题：先调用“上传素材”接口，再把 `file_token` 写到附件字段。
- SDK 关键参数如下：
	- `parent_type` = `bitable_image` 或 `bitable_file`
	- `parent_node` = `app_token`
	- `extra` = `{"drive_route_token": "app_token"}`

## 实际修复点（本项目）
- `feishu_sync/image_uploader.py`
	- 补齐 `parent_type` / `parent_node` / `extra`。
	- 自动根据 MIME 选择 `bitable_image`/`bitable_file`。
- `feishu_sync/sync_manager.py`
	- SDK 客户端设置超时。
	- 表格创建与字段创建分离。

## 验证结果
- 同步 38 条记录成功，图片附件全部上传完成。
- 彻底解决 `1061002 params error` 与上传卡住问题。
