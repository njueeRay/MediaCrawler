## 同步失败（9499 Bad Request）排查记录

本页记录近期同步失败的真实经验，便于后续快速定位。

### 现象
- 批量写入失败，返回 `code=9499, msg=Bad Request`
- 日志有 `log_id`，并提供 Troubleshooter 链接

### 已确认的常见原因
1. **表格 ID 填错**
	 - 错误示例：将 `table_id` 写成 `tblek...&view=...`
	 - 正确：只保留 `tblxxxxx` 纯表 ID

2. **字段值不合法（最常见）**
	 - `NaN` 值：从 CSV/pandas 读入后会出现 `NaN`，飞书接口不接受
	 - 时间戳为浮点：如 `1760173264000.0`，建议转为整数
	 - 空链接对象：超链接字段 `link` 为空会被判非法
	 - 多选字段/附件字段类型不匹配（数组/对象格式错误）
	 - 空行记录（CSV 末尾全空一行）

### 已落地的修复
- **请求/响应体日志**：批量写入失败时打印请求体（字段级别）和响应体，定位到具体字段
- **数据清洗**：在 `data_formatter` 里统一处理
	- `NaN/None` 自动剔除
	- 时间戳浮点转整数
	- 标签列表去空值
	- 空链接自动剔除

### 配置化字段长度（避免硬编码）
- 使用 `.env` 中的配置：
	- `MAX_TITLE_LENGTH`
	- `MAX_DESC_LENGTH`
	- `MAX_TAGS_COUNT`
- `data_formatter` 中已按配置裁剪标题/描述/标签数量

### 推荐排查步骤
1. 打开日志中的 Troubleshooter 链接（优先级最高）
2. 查看 `请求体(仅字段)`，定位是否存在 `NaN`/空对象/类型不匹配
3. 如果是时间字段，确认是否为整数毫秒时间戳
4. 如果是附件/多选字段，确认结构为数组且元素合法
5. 确认表中字段类型与实际写入类型一致

### 关键文件位置
- 请求/响应日志：`feishu_sync/sync_manager.py`
- 数据清洗：`feishu_sync/data_formatter.py`
- 同步配置：`.env`
